# 服务商管理（标准协议）

入口路径： 管理后台 → 服务商管理
在此模块中，管理员可以统一配置和管理企业所使用的 AI 模型来源。Cherry Studio 预置了主流大模型厂商的连接协议，支持一键接入阿里云百炼（通义千问）、DeepSeek、智谱 GLM、月之暗面 Kimi 等主流大模型，以及各类兼容 OpenAI / Anthropic 协议的服务商（如 SiliconFlow 等）。
旗舰版定义的范围 ：指通过标准的 API Key 和 API Host 方式接入的商业化模型服务。
操作： 点击列表页底部的 + 添加服务商 按钮。
系统支持通过预设模板快速接入主流厂商。
| 参数 |
| 说明 |
| 示例值 |
| 自定义显示的名称，方便识别。 |
| code SiliconFlow 或 code DeepSeek官方 |
| 控制该服务商下的所有模型是否对用户可见。 |
| 🟢 开启 |
| strong [关键] 选择对应的协议模板。 br • 接入国内大模型（如通义千问、DeepSeek、Kimi）通常选择 code OpenAI 协议。 br • 部分服务商需选择 code Anthropic 协议。 |
| 从模型厂商后台获取的密钥 (sk-...)。 |
| API 接口地址。选择服务商类型后会自动填充默认地址，使用中转商时需手动修改。 |
技巧 ：大多数国内模型服务商（如阿里云百炼、智谱 GLM、硅基流动）都完美兼容 OpenAI 协议。您只需选择 OpenAI 类型，并填入服务商提供的 Base URL 作为 API Host 即可。
添加服务商后，点击该服务商卡片即可展开模型列表。系统会自动尝试拉取该服务商支持的模型列表，您也可以手动添加。
在模型名称右侧，Cherry Studio 使用图标直观地展示了该模型具备的特殊能力。理解这些图标对于为助手选择合适的模型至关重要。
| 图标 |
| 名称 |
| 含义与应用场景 |
| 🧠 |
| strong 深度推理能力 。代表该模型（如 code DeepSeek-V4 、 code GLM-5.2 、 code Qwen3-Max 正在思考... |
| 🔧 |
| strong 插件/MCP支持 。代表该模型支持 Function Calling 协议。 strong 只有带此图标的模型 ，才能正常使用知识库检索、联网搜索或执行 MCP 工具指令。 |
| 👁️ |
| strong 多模态识图 看见 |
操作： 点击具体模型右侧的 ⚙️ 设置 图标。
为了精确统计企业运营成本，建议管理员详细配置每个模型的计费规则。
- 模型 ID ：API 调用时的真实字符串（不可随意修改，必须与厂商文档一致）。
- 上下文长度 ：限制该模型的最大记忆窗口（如 32k , 128k ）。
- 输入/输出价格 ： 输入价格 ：每百万 Token 的提问费用。 输出价格 ：每百万 Token 的回答费用。 货币类型 ：支持 CNY (人民币) 或 USD (美元)。
为什么配置价格很重要？ 在此处输入的单价未来将直接关联到 [用量统计] 模块。如果留空，后台将无法计算该模型的消耗成本，导致财务报表数据缺失。
配置完成后，为确保 API Key 有效且网络通畅：
- 点击服务商配置栏右侧的 检查连接 按钮。
- 在弹出的对话框中选择一个具体的模型（如 deepseek-chat ）。
- 点击 确认 。
- 成功反馈 检查成功 API Key 有效
Q: 添加了服务商但模型列表是空的？
A: 部分兼容 OpenAI 协议的服务商不支持自动列出模型 ( /v1/models 端点)。此时您需要点击列表底部的 + 添加模型 ，手动输入模型 ID（如 qwen-max ）。
Q: 为什么我的助手无法使用知识库？
A: 请检查该助手使用的模型是否带有 🔧 (工具调用) 图标。部分轻量级模型或旧版模型不支持工具调用，无法触发知识库检索。
