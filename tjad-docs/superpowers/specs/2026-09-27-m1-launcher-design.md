# TJADKnows M1 设计文档：呼出式检索 Launcher + Mac 风格收纳层

日期：2026-09-27（2026-09-28 修订：完整收纳层并入 M1）｜ 状态：待用户评审
上位愿景见会话记忆 `tjadknows-desktop-vision`（企业第二桌面：外壳 A + skill 系统 C 为平台，检索/收纳/桌宠/元宇宙皆为 skill）。M1 是独立可用的第一个落地物，将来作为外壳的第一个内置 skill 与第一个 widget 宿主。

**交付节奏（M1 内部分两阶段，同一代码库同一视觉语言）**：
- **M1a**：检索 Launcher 先行上线内测（自用起步）。
- **M1b**：收纳层三件套（Stacks 归堆 / Dock / Widgets）。

## 1. 目标与非目标

**目标**
- 全局快捷键（默认 Alt+Space / Option+Space，可配置）呼出居中搜索框，Esc 收起，托盘常驻。
- 一次输入，三路联邦检索：WeKnora 知识库（全员可搜全部部门库）、本机文件、本地动作/应用。
- 方向键导航，Enter 执行：知识结果→打开 EKP 原文或 WeKnora 预览；文件→打开/显示所在文件夹；动作→执行。
- 设置页：快捷键、网关地址、订阅部门库、开机自启。
- 双平台：Windows 7–11、macOS 10.15+。内测范围：自用 + 小组。
- **Mac 风格收纳层三件套**（M1b）：Stacks 归堆 + 底部毛玻璃 Dock + Widgets（含知识库速览），设计见 §9。

**非目标（M1 刻意不做）**
- 账号/权限体系（内网 + 网关共享 token 即可）
- 收纳层的**壁纸层深度集成**（隐藏原生桌面图标、窗口钉进壁纸层）——后置 v2，见 §9
- 桌宠、生图、AI 对话 UI（对话用嵌入面板，见 §5）
- 收纳整理、文件索引自建（本机检索完全依赖 Everything/mdfind）

## 2. 技术选型（已定）

**Tauri 2**（Rust 核心 + 系统 WebView + Web 前端）。
- 常驻壳层的资源占用硬约束下是最优解；全局热键/托盘/透明置顶窗口有成熟插件。
- Windows 7 兼容性（已核实）：Tauri 2 官方支持 Win7+，wry 走 WebView2。注意 Microsoft 已于 2023-10 停止 Win7 的 WebView2 更新，最后可用运行时为 Chromium 109——功能可用、需在安装包捆绑 Win7 版离线 WebView2 安装器，且前端 CSS/JS 不得使用 109 之后的新特性。验收时必须找一台真 Win7 机器实测。
- 本机文件检索：Windows 用 Everything SDK（DLL，Rust FFI；要求用户装 Everything 并运行其服务），macOS 用 mdfind（零依赖）。
- 多屏适配：弹窗定位于当前光标所在屏幕，属 UI 层问题，与框架无关。

备选已被否决：Electron（内存/包体对常驻壳层不可接受）；Godot 做外壳（桌面集成能力弱，仅在 M4 元宇宙需要真 3D 时作为独立进程嵌入）。

## 3. 检索架构（核心）

**关键事实（源自 WeKnora 源码核实）**：
- 全局检索 `GET /api/v1/search`：对 title/file_name 做 SQL LIKE，一次覆盖全部库，快但**仅标题级，搜不到正文**。
- 语义/正文检索只有按库的 `POST /knowledge-bases/{id}/hybrid-search`（bge-m3 向量 + 关键词混合），每个请求单独嵌入 query。

**因此检索分两档，由服务端网关（G，部署在 192.168.66.12，与 EKP 管线同机）提供：**

```
客户端 ── /api/instant?q=…  ──→ 网关 ──→ WeKnora GET /search        （0ms 额外成本，标题命中，边输入边出）
客户端 ── /api/deep?q=…     ──→ 网关 ──→ 并行扇出订阅库 hybrid-search
                                          （并发≤8，各库取 top-N，
                                            按 score 归一合并去重，返回 ≤20 条）
```

- **即时档**：输入防抖 ~120ms 直发，结果即时上屏（文件/动作本地结果同样即时）。
- **深度档**：输入防抖 ~450ms 触发，结果追加在即时档下方"深度结果"分区；网络不佳时静默失败，不影响即时档。
- API key 只存网关侧，不下发客户端；网关对内网提供简单共享 token（内测期）。扇出并发限制避免打挂 CPU 上的 bge-m3。
- 知识结果卡片显示：标题、部门库 badge、命中摘要、tag（原部门）；操作：打开 EKP 原文 URL / 在 WeKnora 中查看。

**本机文件**：Windows 走 Everything SDK 进程内查询（毫秒级）；macOS mdfind。结果卡片：文件名、路径、大小、修改时间。

**动作**：本地静态注册表 v1（打开 WeKnora 网页、打开设置、打开指定文件夹等），接口预留 search-provider 形态，与将来 skill 系统一致。

## 4. 客户端结构（Tauri）

```
src/                      # 前端（Vue 3 + TS）
  launcher/               # 搜索框窗口：输入框 + 三分区结果列表 + 预览条
  organizer/              # 收纳层画布（M1b）：Stacks / Dock / Widgets，透明全屏层
  settings/               # 设置窗口
src-tauri/
  hotkey.rs               # 全局热键注册/重注册
  search/                 # everything.rs (FFI) | mdfind.rs | actions.rs
  gateway.rs              # 网关客户端（instant/deep，重试与超时）
  watch.rs                # 桌面/常用文件夹变更监听（Win: ReadDirectoryChangesW；mac: FSEvents）
  tray.rs / windows.rs    # 托盘、窗口定位（光标所在屏）、开机自启、单实例
```

- 搜索框为独立小窗口（非主窗口），失焦即收起；单实例锁防止重复启动。
- 所有 WeKnora 流量只经网关，客户端不感知 API key。

## 5. "问一问"嵌入面板（可与 M1b 并行的小增量）

WeKnora 有正式 Embed Channel 体系（`/embed/:channelId` + 发布 token + CSP 来源白名单 `embed_allowed_origins` + 匿名会话交换），在 launcher 结果页底部放"问一问 AI"入口，展开 iframe 嵌该渠道页——KB 问答/引用/会话全部复用 WeKnora 自带 UI。

前置条件（管理员操作）：在 WeKnora 后台创建 embed 渠道（指向全部部门库或指定库），把 launcher 的 origin（tauri 自定义协议，如 `tauri://tjadknows`）加入渠道白名单。

## 6. 错误处理与降级

| 情况 | 行为 |
|---|---|
| 网关不可达 | 深度档静默消失，托盘图标变灰提示；即时档与本地检索不受影响 |
| Everything 未运行（Win） | 本地文件分区隐藏，设置页给"启动 Everything"引导 |
| hybrid-search 扇出超时（>3s） | 返回已完成的库的结果，缺失库标记"部分结果" |
| Win7 WebView2 缺失/过旧 | 安装器捆绑离线运行时；启动失败时给出下载指引页 |
| 低端机全屏毛玻璃卡顿（Win7 老机器，109 可能走软渲染） | 自动降级：减小 blur 半径→改半透明纯色；设置页提供手动档位 |
| 堆栈源文件夹监听丢失事件（休眠/网络盘断连） | watch.rs 指数退避重建监听 + 周期性全量对账（<5s 完成） |

## 7. 测试与验收

- 单元：网关合并/去重/归一逻辑（Rust 侧 + 网关侧）、动作注册表。
- 集成：对真实 WeKnora 的 instant/deep 冒烟（16,767 文档、44 库真实数据）。
- 手工验收清单：Win7/Win10/Win11/macOS 各一台；双屏与单屏；Alt+Space 与系统冲突时的备选键；内测 3-5 人一周日常使用反馈。
- M1b 增补：全屏毛玻璃在 Win7 真机的帧率实测（触发降级档位验证）；堆栈规则引擎对 500+ 文件桌面的归堆耗时（<2s）；拖拽堆栈展开/收起的动效流畅度。
- 性能预算：冷启动 <1.5s，呼出 <200ms，即时档首结果 <300ms（内网）；收纳层常驻内存 <150MB（超出即减 blur/减 widget 数量）。

## 8. 视觉语言（全产品统一，Mac 风格）

用户明确：产品整体走 Mac 风格，不只是收纳层。设计语言基线（M1 的搜索框即生效）：

- **材质**：毛玻璃（CSS `backdrop-filter: blur`，Chromium 109 支持，Win7 无碍）、半透明深/浅双色主题、12–16px 圆角、1px 细描边（低透明度白/黑）、多层柔和阴影。
- **字体**：中文苹方/HarmonyOS Sans，西文 SF Pro 系替代（系统栈回退）。
- **动效**：呼出缩放淡入（120–180ms）、结果列表 stagger 入场、hover 微浮起。动效全部可关（性能与晕动症友好）。
- 密度克制：信息分层靠留白与字重，不靠分割线。

## 9. 收纳层设计（M1b，Mac 风格，用户已确认三件套全套）

**定位**：盖在 Windows/macOS 桌面上的一层"第二桌面"，把杂乱桌面变成 Mac 式整洁画布，同时是知识库的天然入口。用户已确认完整三件套并入 M1。

**三件套**：
- **Stacks 归堆**：按可编辑规则（类型/日期/项目/自定义通配）把桌面文件自动归堆为 Mac 风格堆栈；点击以扇形/网格展开；堆栈右上角角标显示数量。规则引擎 v1 只做"类型 + 修改日期 + 关键词"三类维度。
- **Dock**：底部毛玻璃 Dock，固定区（常用应用、知识库速览入口）+ 最近使用区。
- **Widgets**：时钟/日历、WeKnora 知识库速览（今日新增文档、收藏）、便签。widget 与收纳画布同层渲染。

**技术分期（关键决策）**：
- **v1 = 透明覆盖层**：Tauri 透明全屏窗口（失焦点击穿透、widget/堆栈区域可交互），展示自己的堆栈画布，**完全不动原生图标**。风险低，Win7/Win10/11 行为一致。呼出方式：快捷键 + 可选热角。
- **v2 = 深度集成**（后置，评估后再立项）：隐藏原生桌面图标、窗口钉进壁纸层（Win32 WorkerW/Progman 方案）。这是 Fences 类产品迭代多年的深水区，杀软/系统更新易碎，且 Win7 无 Win11 的圆角/亚克力 API，需降级样式。
- 堆栈内文件为真实文件引用：打开 / 显示所在文件夹 / 拖出。**拖拽入库**（拖文件到"知识库"区上传 WeKnora）在收纳层就绪后接 M3 的 ai-action。
